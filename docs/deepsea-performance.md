# 海底性能修复

## 刚进入海底地图

地形兼容迁移提前到 `WorldLoadEndEvent`，在原生生成模式结束、建筑邻接、资源索引和渲染缓存初始化之前批量完成，避免进图后逐格触发索引／绘制缓存更新。同一轮加载的后续 `WorldLoadEvent` 和 `SaveLoadEvent` 复用迁移结果，不重复全图扫描；新一轮加载即使复用相同尺寸的地块容器也会重新检查。

兼容扫描在循环外解析方块引用。旧地形转换用一次建筑占用前缀和计算替代每格5×5邻居查找，并跳过不会种植植物的地板上的噪声采样，维持原有布局。

`tools/DeepSeaStartupCheck.java` 的28800格旧地形测试保持了完全相同的地板、矿脉、植物哈希与基地库存；加载后的24696次逐格地板更新降为0，重复保存加载事件的28800格扫描降为0。耗时记录仅用于排查，不能当作玩家实际帧率。

## 重复的盟友关系检查

原先每次建筑、单位及弹体进入盟友查询环境，都会再次遍历全部活动阵营并检查敌对核心表。现在保留逐帧刷新，并在原生核心变化替换敌对数组时立即刷新；普通实体更新复用已经检查的数组。没有盟友关系的敌对阵营在最外层更新中直接使用原生索引，嵌套的攻击／死亡回调仍保留正确视角。地图重置时清除缓存，避免保留上一张地图的阵营对象。

计数回归中，2000次玩家阵营更新原先触发10000次活动阵营表遍历，修复后只有筛选当前视角所需的2000次，不再重复检查整张关系表。

## 潜艇侦测

侦测改为只查询观察者阵营的单位和建筑四叉树，发现一个有效侦测者就停止。移除其他阵营建筑扫描和临时结果数组；保持即时的位置、距离及建筑有效性判定，不使用有延迟的可见性缓存。盟友视角直接保留可见性。

## 天气与环境

海底悬浮粒子根据可视范围调整间距，计入边缘填充后最多绘制512个粒子单元，每个粒子的多边形顶点数也固定。普通视距保留原密度，缩小视角不再让绘制量随可视面积持续增长。

寒冷／深海环境没有待转换的重结晶单位时，仅在原有30帧环境施加周期执行单位遍历，跳过其余29帧的空检查。有重结晶单位时继续正常冻结和转化。

## 验证范围

`tools/DeepSeaPerformanceCheck.java` 统计真实游戏索引访问次数和环境更新遍历次数，并检查宽屏、负坐标及极远视角的天气粒子上限。另以潜艇侦测、盟友战斗、重结晶行为及存档测试检查功能回归。

这些是针对已确认热路径的逻辑与绘制量检查，不是玩家实际地图的FPS测量；当前受限环境无法启动桌面图形界面。
