# 地图盟友阵营

在地图编辑器打开 **菜单 → 盟友阵营**。勾选需要与地图玩家结盟的阵营后，正常保存地图即可。可选择原版、模组以及地图上已放置的其他阵营。

勾选的阵营与地图规则中的玩家阵营组成同盟，盟友之间也互不攻击。取消勾选后恢复敌对关系。玩家阵营以地图的 `defaultTeam` 为准，不限定为蓝队。

各阵营仍拥有独立的核心、建筑、库存、单位和指挥权。玩家不能框选指挥或附身盟友单位，也不能配置盟友建筑。盟友不改成玩家队伍，不自动共享资源。

勾选盟友时默认启用原生自主作战和自主建造 AI，也可在界面中分别关闭。自主作战由盟友自行组织军队、选择敌人和保卫基地；自主建造使用原生基地建造 AI。地图作者仍需布置适合该阵营的核心、资源和生产设施；系统不自动开启无限资源或作弊。

盟友关系通过地图规则标签 `cryon-allied-teams` 保存，内容为盟友阵营 ID 的逗号分隔列表。自主 AI 开关使用原生阵营规则。地图、存档及联网规则传输均沿用游戏的序列化格式；没有盟友设置的地图保持原有阵营关系。

## 实现与兼容

原版以不同阵营为敌人，未提供完整的外交接口。本模组只在配置了盟友的地图中，为建筑和单位创建继承原实现的原生子类，保留实体 ID、单位控制器及原有行为。索敌时暂时排除其他盟友，操作结束后恢复索引；子弹碰撞、激光、范围伤害和带来源阵营的延迟建筑伤害也遵循盟友关系。自主军队与建造 AI 使用同样的索敌规则。

本模组的特殊护盾、压制、干扰、转化、黑洞、轨道打击和核武器另行检查盟友关系，避免特殊效果绕开普通武器的友军保护。进攻地图在只剩同盟核心时可以正常获胜。

运行时子类使用游戏自带的 Rhino 字节码生成器及平台类加载器，不修改游戏文件。已对原版与当前模组提供的全部建筑和单位构造器进行验证。其他模组若提供不可继承或非公开的实体类，需要另做适配。

Rhino 脚本通过 `JavaAdapter`／`extend` 生成的建筑也会适配：构造时传递该实例的脚本委托、上下文工厂和所属方块，由 Rhino 为新建筑重新绑定 `this`，保留脚本更新与存档回调。`tools/AllianceScriptAdapterCheck.java` 覆盖普通建筑及内部炮塔建筑的建造完成和存档重载路径。

## 验证

`tools/MapAlliancesCheck.java` 在独立临时目录加载打包模组，验证双方索敌、独立 AI、玩家指挥与附身限制、弹体碰撞、激光穿透、范围伤害、延迟爆炸、原生炮塔、自主进攻、资源独立、存档重载、取消结盟、胜利条件和地图间隔离。

```bash
mkdir -p /tmp/cryon-allies-tests
javac --release 17 -sourcepath '' \
  -cp /path/to/mindustry-assets/mindustry-linux-64-bit/jre/desktop.jar \
  -d /tmp/cryon-allies-tests tools/MapAlliancesCheck.java
java -cp /tmp/cryon-allies-tests:/path/to/mindustry-assets/mindustry-linux-64-bit/jre/desktop.jar \
  MapAlliancesCheck
```

无窗口验证不会修改玩家已安装模组或存档。当前受限环境无法启动桌面图形界面，按钮布局需要在本地游戏中检查。
